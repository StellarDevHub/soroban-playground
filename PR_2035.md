## Summary

Implements a deterministic wallet-connection finite state machine and reconnect resiliency for `WalletProvider` (FRONTEND-265 / #2035).

Previously the provider mutated a loose `status` string from many async callbacks, with no formal transition rules, no guard against late state updates after unmount, and no explicit recovery path for a stale session. Switching wallets (Freighter / xBull / Albedo / Ledger) could therefore leave orphaned listeners, unhandled rejections and deadlocked UI state.

## Changes

- Added `frontend/src/lib/wallets/connectionMachine.ts`: canonical states `disconnected -> connecting -> connected -> signing -> error`, an explicit transition table, `canTransition` / `transition` / `transitionStrict`, a reducer, and a stable mapping to the public status (`unavailable` is a UI override of `error`). Illegal events are no-ops, so async races can never produce an undefined state.
- Reworked `WalletProvider` to drive every lifecycle change through the FSM:
  - `connect`, `disconnect`, `reauthenticate`, `signTransaction` and session restore now dispatch FSM events instead of setting `status` directly.
  - Added a real `signing` state and guarded signing against concurrent calls.
  - User rejection / Horizon revalidation failures move the machine to `error`; account rotation and Ledger timeouts move it to `disconnected` with reauthentication required.
- Added mounted lifecycle guards: a `mountedRef` plus `useGuardedState` wraps every state setter, `send()` is mount-guarded, and all async continuations (wallet discovery, connect, sign, adapter account/network callbacks) check `mountedRef.current` before dispatching. Listener cleanup is preserved.
- Auto-reconnect: persisted sessions are structurally parsed and freshness-checked (`isSessionFresh`) before adoption on page refresh, the machine walks `CONNECTING -> CONNECTED`, and a public `reconnect()` helper allows recovery from a stale/deadlocked session without clearing browser storage.
- `ConnectionStatus` now includes `signing`; `WalletContext` exposes `connectionState` and `reconnect`.
